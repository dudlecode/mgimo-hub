# Безопасность «Атташе»

## Простыми словами
- **Вход**: логин и пароль. Пароль никогда не хранится — только его «отпечаток» (хэш argon2id, современный стандарт, медленный для перебора).
- **Сессия**: после входа браузер получает случайный ключ в защищённой cookie (недоступна JavaScript-у, отправляется только на наш сайт). В базе хранится не сам ключ, а его хэш — даже утечка базы не даст войти.
- **Свои данные**: сервер узнаёт студента по сессии и выдаёт только его записи. Номер заявки в адресе — лишь «какую из моих». Чужая заявка → «Страница не найдена».
- **Перебор паролей**: после 5 неудачных попыток вход по этому логину с этого адреса блокируется на 15 минут. Блокировка считается по паре «логин и адрес», иначе любой посетитель пятью неверными паролями закрывал бы чужой аккаунт для всех. От распределённого перебора страхуют лимит по адресу (30 неудач) и общий предел по логину (100 неудач за 15 минут).
- **Ключи сервисов** (DeepSeek) — только в переменных окружения сервера. В браузер не попадают никогда.
- **Справка с QR**: страница проверки показывает минимум — номер, тип, дату, инициалы и факультет. Без даты рождения, контактов и оценок.

## Модель угроз (STRIDE, кратко)
| Угроза | Пример | Защита |
|---|---|---|
| Spoofing | подбор пароля | argon2id, лимит попыток (login + IP, хранится в БД → работает на нескольких серверах), одинаковое время ответа для несуществующих логинов |
| Spoofing | кража сессии | httpOnly + SameSite=Lax + Secure cookie, токен 256 бит, хэш в БД, срок 7 дней, отзыв сеансов в профиле |
| Tampering | подмена `studentId` в форме | studentId никогда не принимается от клиента — только из сессии |
| Tampering | CSRF | Server Actions проверяют Origin (Next.js), SameSite=Lax, Route Handlers проверяют Origin вручную |
| Repudiation | спор по статусу заявки | история событий заявки с автором и временем |
| Information disclosure | IDOR: `/requests/<чужой id>` | все запросы фильтруются по `studentId` из сессии, промах → 404; id — UUID |
| Information disclosure | XSS | React экранирует вывод, строгая CSP, без `dangerouslySetInnerHTML` для пользовательских данных |
| Information disclosure | утечка через ИИ | ассистент получает только данные текущего студента; ключ на сервере; промпт-инъекции не дают действий без подтверждения |
| DoS | спам ИИ-запросами | лимит запросов к ассистенту на пользователя |
| Elevation | студент открывает `/staff` | проверка роли в layout и в каждом экшене сотрудника |

## Инварианты для разработчиков (и ИИ-агентов)
См. `CLAUDE.md` → «Инварианты безопасности».

## Проверка
`npm run test:security` — скрипт логинится двумя студентами и сотрудником и проверяет:
- студент А не открывает заявку, документ и дисциплину студента Б (404);
- студент не открывает `/staff`;
- неавторизованный запрос перенаправляется на вход;
- в cookie флаги httpOnly и SameSite;
- в ответах страниц нет хэшей паролей и токенов;
- лимит попыток входа срабатывает.

## Заголовки
CSP (`default-src 'self'`, `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS в продакшне. См. `next.config.ts`.

## ИИ-ассистент
- Ключ DeepSeek — только в переменной окружения сервера (`DEEPSEEK_API_KEY`), запросы к API идут только с сервера.
- В контекст модели попадают только учебные данные текущего студента; телефон, почта, дата рождения, номера зачётки и студенческого — не передаются.
- Ответ модели — JSON; каждое предложенное «действие» проверяется на сервере (тип заявки из каталога, значения полей из списка, курсы — только свои, ссылки — только внутренние). Модель не может отправить заявку: она открывает форму, студент проверяет и отправляет сам.
- Лимит: 20 вопросов за 10 минут на пользователя (хранится в БД). Проверка Origin — защита от CSRF.
- Для промышленной эксплуатации: модель на собственной инфраструктуре или российский провайдер с договором по 152-ФЗ.

## Новые разделы (этап 11)

### Запись на приём
- Двойную запись на один слот отсекает база: частичный уникальный индекс `(faculty_id, starts_at) WHERE status = 'booked'`. Лимит двух активных записей держит блокировка строки студента (`SELECT ... FOR UPDATE`) в транзакции.
- Время от клиента перепроверяется на сервере: рабочий день, точное начало слота, не раньше чем через час. Чужой талон и чужой `.ics` дают 404.

### Больничный и файл справки
- Загрузка только через Route Handler: сессия студента, проверка Origin, `Content-Length` до 5 МБ, тип по сигнатуре файла (PNG, JPEG, PDF), расширение и mime должны совпадать с найденным типом, имя очищается, считается sha256. Диагноз не спрашиваем и не храним.
- Выдача: только владельцу и сотруднику его области, иначе 404. Заголовки: `Content-Security-Policy: sandbox; default-src 'none'`, `nosniff`, `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`. Правило для этого пути стоит в `next.config.ts` после общего, иначе общий CSP перезаписал бы заголовок маршрута. PDF отдаётся на скачивание: встроенный просмотрщик браузера в песочнице не работает.

### Офлайн-кэш (service worker)
- На устройстве в Cache Storage лежит HTML своих страниц: расписание, баллы, профиль, документы с QR. Доступен только скриптам своего сайта, без шифрования (защищает блокировка устройства).
- Никогда не кэшируются: `/api/*`, `/staff/*`, `/login`, `/verify/*`, не-GET запросы, Server Actions, RSC-ответы и редиректы.
- Кэш страниц стирается на странице входа (сюда ведёт выход) и при любом ответе с переходом на вход, поэтому следующий пользователь устройства не увидит чужие данные. Счётчик очисток не даёт фоновой записи, начатой до очистки, сохраниться после неё.

### Push-уведомления
- Приватный VAPID-ключ только в env сервера, публичный передаётся пропсом без `NEXT_PUBLIC_`.
- Подписка: Origin, сессия, тело до 4 КБ, zod; адрес подписки только `https` и только хосты push-сервисов браузеров (FCM, Mozilla, Apple, WNS), потому что сервер сам ходит по этому адресу (защита от SSRF). Не больше 10 подписок на пользователя, мёртвые (404/410) удаляются.
- Текст уведомления виден на заблокированном экране. Для оценок, здоровья, оплаты и сообщений офиса в push уходит только заголовок и фраза «Откройте MGIMO Hub, чтобы прочитать»; подробности видны после открытия. На странице входа устройство отписывается, а переписка с Атташе в этой вкладке стирается.

### Оплата обучения
- Только показ: платёжных форм и платёжного QR нет, реквизиты на квитанции-образце из нулей. Студент ничего не может изменить.
- Напоминание офиса не чаще раза в сутки на платёж: условие паузы и области сотрудника стоит прямо в `UPDATE`, двойной клик не задваивает уведомление.

### Журнал действий
- Таблица `audit_log` только дописывается: `UPDATE` и `DELETE` запрещены триггером PostgreSQL (`drizzle/0004_audit_append_only.sql`), поэтому даже с доступом приложения к БД запись нельзя подчистить. Внешних ключей нет, чтобы запись пережила удаление пользователя.
- Исполнитель берётся из сессии, а не из аргументов. В тексте записи нет персональных данных, только что сделано.

## Найдено автотестом
Детальные страницы с id в адресе изначально отдавали HTTP 200 (на этапе 11 ошибку независимо повторили два агента, в записи на приём и в квитанции об оплате) с экраном «не найдено»: `loading.tsx` начинал потоковую отдачу раньше, чем срабатывал `notFound()`. Данные не утекали, но статус был неверным. Исправлено: скелетоны загрузки — только на списочных страницах, детальные — без стриминга, теперь честный 404.

## Персональные данные
Все данные вымышлены. Минимизация: в интерфейсе телефон и номер зачётки частично скрыты (показать — по нажатию), на странице проверки справки — только инициалы.
