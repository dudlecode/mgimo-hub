# Журнал процесса: как «Атташе» создавался с ИИ

Этот файл ведут ИИ-агенты и автор по ходу работы. Из него собирается итоговый отчёт для жюри.
Формат записи: этап → что сделали → ключевой промпт/решение → что пошло не так и как исправили.

## Инструменты
| Инструмент | Для чего |
|---|---|
| Claude Code (desktop, модель Claude Opus) | основной агент: архитектура, код, документы, ревью |
| Субагенты Claude Code (Sonnet) | параллельные исследования: факты о МГИМО, боли студентов и бенчмарк |
| Встроенный браузер Claude Code | проверка интерфейса, скриншоты на 360 px |
| Playwright (системный Chrome) | e2e-тесты и разовые прогоны агентов на этапе QA, скриншоты |
| DeepSeek V3.2 в Amazon Bedrock (us-east-1) | ИИ-ассистент «Атташе» внутри кабинета (рантайм) |
| Docker | локальная база и сборка для передачи |

## Этап 0. Постановка (2026-11-06)
- Автор передал ТЗ хакатона. Агент разобрал критерии оценки и предложил план: концепция, стек, безопасность, этапы, что должен сделать человек.
- Решение: кабинет под МГИМО (организатор хакатона), хотя автор не студент МГИМО → реалии берём из открытых источников, вместо опроса однокурсников — кабинетное исследование + синтетические персоны (явно помечены) + анкета для реальных студентов.
- Решение по ИИ в рантайме: DeepSeek (доступен из РФ, OpenAI-совместимый API) вместо GigaChat — по выбору автора.
- Решение по хостингу: передаётся третьей стороне → упаковываем в Docker Compose; рекомендуем российский хостинг (Vercel/Cloudflare в РФ работают нестабильно).

## Этап 2. Каркас и документы для ИИ
- `create-next-app` поставил Next.js 16.4 с `cacheComponents` и `partialPrefetching` по умолчанию, а сгенерированный `AGENTS.md` предупредил: «This is NOT the Next.js you know».
  Агент прочитал версионную документацию из `node_modules/next/dist/docs` (гайд «Authentication with Cache Components», upgrade guide v16) и **сознательно выключил cacheComponents**: в кабинете каждая страница персональная, выигрыша нет, а каждый доступ к cookies пришлось бы оборачивать в Suspense. Учтено: `middleware` → `proxy`, асинхронные `params`/`cookies()`.
- ORM: в npm последняя Prisma — release candidate 8.0 (`latest` = rc) → выбран Drizzle ORM 0.45 (стабильный, чистый TypeScript, без бинарного движка — проще Docker).
- Шрифты через `@fontsource` (самостоятельный хостинг, сборка не зависит от Google Fonts).
- Созданы документы для агентов: `CLAUDE.md` (правила и инварианты безопасности), `docs/PRD.md`, `docs/DESIGN.md`, `docs/SECURITY.md`.

## Этап 3. Данные и вход
- Схема на 22 таблицы (`src/db/schema.ts`): студенты, группы, курсы с записью (языковые подгруппы — через enrollments), контрольные точки, зачётка, занятия с полями изменений («было → стало»), заявки с историей, уведомления, объявления с аудиторией, сессии, попытки входа.
- Генератор демо-данных с детерминированным ГСЧ: даты строятся от текущего дня, поэтому кабинет всегда «живой». Три сюжета студентов: отличница с повышенной стипендией под вопросом, студент с долгом и угрозой допуска, первокурсница из Одинцово (пустые состояния).
- Вход: argon2id, токен 256 бит, в БД — SHA-256 токена, лимит попыток в БД (работает на нескольких серверах), «пустышка»-хэш против перебора логинов по времени ответа.

## Этап 4. Интерфейс студента и сотрудника
- Экраны: Сегодня, Расписание (день/неделя, свайп), Учёба (семестр/сессия/зачётка + калькулятор «что если»), Заявки (каталог, формы, трекер, документ с QR), Уведомления/новости, Профиль (электронный студенческий, сеансы), кабинет сотрудника (очередь, обработка, объявления, изменения расписания).
- Проверка в встроенном браузере на десктопе и на 360 px после каждого крупного блока.

## Этап 5. ИИ-ассистент «Атташе»
- DeepSeek в JSON-режиме: модель возвращает `{reply, actions}`, сервер **проверяет каждое действие** по белому списку (типы заявок, значения полей, свои курсы, внутренние ссылки) — модель не может ни отправить заявку, ни увести на чужой сайт.
- Контекст — только данные текущего студента и без лишнего (нет телефона, почты, даты рождения, номера зачётки).
- Офлайн-режим на правилах: работает без ключа и при сбое API — демо не ломается.

## Этап 6. Проверка
- `scripts/security-check.ts` — 27 автопроверок (IDOR, роли, cookie, заголовки, хэши, лимит попыток, CSRF ассистента, минимум данных на странице проверки справки).
- Проверка вёрстки на 360 px по всем основным экранам скриптом (`scrollWidth === innerWidth`).

## Этап 7. Подключение модели через Amazon Bedrock
- Автор получил доступ к DeepSeek V3.2 в Amazon Bedrock (us-east-1). Агент нашёл в документации AWS точный ID модели `deepseek.v3.2` и способы доступа (Converse API, OpenAI-совместимый endpoint).
- Выбран Converse API: поддерживает и API-ключ Bedrock (Bearer), и ключи IAM (подпись SigV4 через `aws4fetch`, MIT) — неважно, какой ключ выдали.
- JSON-режима у Converse нет → ответ модели разбирается устойчиво (`extractJson`: снимает ```json-обёртку, ищет объект). Действия по-прежнему проверяются по белому списку.
- `npm run ai:check` — проверка подключения без вывода ключей: API-ключ Bedrock (Bearer), ответ за ~1,8 с.
- Живой прогон: расписание с отменой, расчёт баллов, черновик справки для визы (страна, даты, цель — заполнены сами), попытка получить чужие оценки — вежливый отказ.

## Этап 8. Редизайн по обратной связи автора
- Автор отклонил v1: «нейрослоп», плохие оттенки. Агент разобрал признаки шаблонного ИИ-дизайна (градиенты, «золото», засечки, иконки в плашках, бежевый фон, синюшная тёмная тема) и предложил три направления с превью; автор выбрал «строгий» и кобальтовый акцент.
- Агент загрузил навык редизайна (аудит типовых ИИ-паттернов) и переделал систему: токены, шрифт Geist + Geist Mono, базовые компоненты, оболочку, все экраны. Массовые правки скриптами, точечные вручную; после каждого блока проверка в браузере и на 360 px.
- Решения автора: продукт называется MGIMO Hub (ассистент остаётся «Атташе»), новый монохромный знак, без длинных тире и стрелок, без пометок «концепт / неофициальный / данные вымышлены» в интерфейсе. Агент сохранил только водяной знак «образец» на справках (защита от подделки документа) и объяснил почему.
- Чистка текстов: 134 длинных тире, 20 стрелок и 17 коротких тире заменены по правилам (метки через двоеточие, связки через запятую, «ауд. 4105 вместо 4021»); для ответов модели добавлены правило в промпте и автозамена.
- Скриншоты: `docs/screenshots/v1/` (отклонённый вариант) и `docs/screenshots/v2/`.

## Этап 9. Страница входа с заставкой «чернила»
- Автор отклонил простую форму: нужен вход справа, появление логотипа, его уход в сторону и чернила на фоне.
- Агент сделал WebGL-шейдер «тушь в воде» (fBm с domain warping, монохром, инверсия в тёмной теме, пониженное разрешение ради батареи, пауза в фоне, статичный кадр при reduced motion) и сцену на motion: логотип проявляется в чистом центре, чернила сжимаются в панель (clip-path), логотип общим layoutId переезжает к форме.
- Ошибки по ходу: заставка не показывалась в dev из-за двойного монтирования (флаг ставился при монтировании, перенесён на конец заставки); три итерации шейдера по скриншотам (серый мрамор, «пустота», плоские плато, затем плавный контрастный вариант).
- Убран значок Next.js в режиме разработки (`devIndicators: false`).

## Этап 10. Полировка по обратной связи и ИИ для деканата
- Профиль перестроен на ровную сетку, увеличены отступы на всех страницах (21 файл), у деканата цифры без иконок-плашек.
- Только две темы (светлая и тёмная), по умолчанию тёмная.
- Анимации по навыку page-load-animations: переход страниц (пружина 300/30), каскад секций 60 мс, каскад строк списков на CSS, рост прогресс-баров, счётчики, скользящий индикатор вкладок (layoutId), «щелчок» чекбокса; всё уважает reduced motion.

## Этап 11. Продуктовые разделы для деканата и студентов (параллельные агенты)
- Автор выбрал из списка идей: радар рисков, аналитику с «паучьими» диаграммами, запись на приём; для студентов офлайн и push, оплату обучения для контрактников, кошелёк документов, больничный, английский интерфейс; для деканата карточку студента, журнал действий и пересдачи. Рассылки по сегментам и темы вопросов к Атташе автор отклонил.
- Организация: независимые разделы раздаются фоновым агентам, у каждого свой список файлов и запрет трогать чужие. Общие точки (меню, схема БД) правит основной агент заранее.
- Решение: все новые таблицы (оплата, больничный, push-подписки, пересдачи, журнал) описал основной агент одной серией миграций до запуска агентов. Причина: два агента, одновременно генерирующие миграции Drizzle, ломают журнал снимков схемы.
- Журнал действий только дописывается: UPDATE и DELETE запрещены триггером в PostgreSQL (миграция `0004_audit_append_only`), внешних ключей нет, чтобы запись пережила удаление пользователя. Полный пересид использует TRUNCATE, который построчные триггеры не вызывает.
- Запись на приём: слоты считаются из часов работы офиса, двойную запись на один слот отсекает частичный уникальный индекс PostgreSQL (`WHERE status = 'booked'`), лимит двух активных записей держит блокировка строки студента в транзакции. Проверено двумя одновременными вставками.
- Аналитика: свои SVG-диаграммы без библиотек (паучья, площадь, бары, тепловая карта), у каждой скрытая таблица данных для скринридеров; оси паучьих диаграмм нормированы 0-100, формулы показаны на странице. Для правдоподобных графиков сид дописывает 300 исторических заявок за 10 недель. Наружу уходят только агрегаты, без ФИО.
- Оплата обучения для контрактников: только показ (график, квитанция-образец без платёжного QR и с реквизитами из нулей), напоминания офиса не чаще раза в сутки на платёж, условие паузы стоит прямо в UPDATE, поэтому двойной клик не задвоит уведомление.
- Больничный: студент открывает больничный в день болезни, видит затронутые пары и дедлайны, Атташе пишет письмо преподавателю о переносе; закрывает справкой (JPG, PNG, PDF до 5 МБ, тип по сигнатуре файла, sha256, хранится в БД). Диагноз не спрашиваем. Файл отдаётся только владельцу и сотруднику его области, `no-store`, `nosniff`, `sandbox`.
- Офлайн и push: свой service worker без библиотек. Страницы студента сохраняются после удачного ответа (сеть с таймаутом 3 с, затем копия), `/api`, `/staff`, `/login`, Server Actions и редиректы не кэшируются никогда. `experimental.useOffline` сознательно не включён: без него Next 16 при обрыве делает обычный переход, и SW отдаёт сохранённую страницу, а с ним переход висел бы на скелетоне. Кэш стирается на странице входа и при любом редиректе на неё, устройство отписывается от push. Push: VAPID-ключи только в env, адрес подписки разрешён только у известных push-сервисов (защита от SSRF), в тексте уведомления нет подробностей. Проверено харнессом с моками Cache API (26 проверок) и в браузере; настоящий офлайн и доставка на телефон не проверены.
- Кошелёк документов: студбилет и все готовые справки с QR на одной странице, сохраняются для работы без сети.
- Пересдачи: долги собираются по дисциплинам и группам; «Предложить дату» ищет рабочий день через 7-14 дней, когда у группы и преподавателя нет пар и других пересдач, и аудиторию, свободную во всём университете, объясняя выбор одной строкой. «Выпустить направления» в одной транзакции (блокировка строки и advisory lock на нумерацию) создаёт направления, ставит дату в зачётку и закрывает заявления «Пересдача»; уведомления уходят после фиксации. «Не явился» попытку не тратит.
- Карточка студента и журнал: карточка собирает риск, баллы, долги и пересдачи, заявки, больничные, оплату, записи и действия сотрудников; без `loading.tsx`, чтобы чужой id давал честный 404. Ссылки на карточку с `prefetch={false}`: иначе предзагрузка писала бы просмотр в журнал. Просмотры пишутся не чаще раза в 10 минут на сотрудника и студента. Вход сотрудника пишется через `after()`, чтобы время ответа не выдавало, что логин принадлежит сотруднику. 25 кодов действий (вместе с пересдачами), в тексте записей нет оценок, сумм и текстов сообщений. Блок «Кто обращался к вашим данным» в профиле студента убран по решению автора: журнал нужен деканату, студенту он не показывается.
- Английский интерфейс: язык в cookie, словари по разделам через `defineMessages(ru, en)` (английский словарь обязан совпасть с русским по ключам, иначе ошибка типов), форматтеры дат с параметром языка, английские названия дисциплин и факультетов в БД. Кабинет сотрудника, бланки справок, квитанции и письма преподавателям остаются на русском: это официальные документы и русскоязычные адресаты.
- Радар рисков: балл из долгов, угрозы допуска, дисциплин ниже 60 %, среднего результата и заявок без ответа; четыре SQL-агрегата на всю область без N+1; черновик сообщения студенту пишет модель, при её недоступности шаблон.

- Сборка этапа: все модули сида подключены в `src/db/seed/index.ts`, `npm run db:reset` проходит с нуля (61 студент, 300 исторических заявок, 25 записей, 29 контрактников, 15 долгов и 8 направлений). `tsc` и `eslint` чистые, `next build` собирает 55 маршрутов, `npm run test:security` на свежей базе: 46 из 46. В браузере проверены аналитика, карточка студента, вход и кабинет студента на английском, шесть страниц на 360 px без горизонтальной прокрутки.
- Найдено при сборке: агенты писали в общий scratchpad и перезаписывали файлы друг друга, а общая очистка curl-сессий выбивала чужие проверки. Дальше у каждого агента своя метка User-Agent для сессий и своя папка.

- Docker-образ пересобран после этапа 11 (новые пакеты для push, VAPID-ключи в окружении): сборка проходит, контейнер стартует за 4 секунды, миграции применяются, push в production включён, ИИ отвечает через Bedrock, заголовок `sandbox` у файла справки доходит до браузера, `npm run test:security` на образе: 46 из 46. Живой вопрос к Атташе в контейнере нашёл ошибку 30 (не знал о выпущенном направлении), исправлено и пересобрано. Из комментариев Dockerfile и docker-compose убрано слово «концепт».
